IVMS101 Skeleton Validator

Checks the structure of an IVMS 101.2023 travel-rule payload before any real customer data is ever typed into it. The payload arrives as a zero-PII skeleton: every free-text field is either the literal SYNTHETIC or a length marker such as {"len": 12}, and the tool verifies the required entities, multiplicities, max lengths, code lists and the C1–C12 constraints of the pinned interVASP standard against that skeleton. Any field holding real-looking free text is refused, naming the JSON path only.

🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
The skeleton form

A skeleton replaces every free-text leaf with one of two placeholders. A SYNTHETIC string marks "some value belongs here"; a {"len": n} object additionally declares the intended character length so the tool can check the datatype's maximum (for example, Max35Text admits at most 35). Enumeration leaves stay real, because codes are not personal data: country values must be ISO-3166-1 alpha-2 or XX, and name, address and national-identifier type codes must come from the pinned IVMS 101.2023 code lists. The declared ivms101_edition must equal 101.2023; anything else fails closed. The tool's output carries JSON paths, rule ids and standard sections only, and never echoes a leaf value.
