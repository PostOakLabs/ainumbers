Circle Arc L1 · Technology Facts
What is Arc?

Arc is Circle's EVM-compatible Layer 1 blockchain, purpose-built for financial use cases. It uses USDC as the native gas token, so agents and users never need ETH on Arc. Consensus is Malachite BFT with ~350ms finality. Public testnet launched Oct 2025; mainnet expected 2026.

Arc's key primitives: Circle Payments Network (CPN) for global USDC settlement corridors, StableFX for 24/7 on-chain FX (atomic Payment-versus-Payment, PFMI P12 compliant), xReserve for on-chain USDC/USYC reserve management, ERC-4337 Paymaster for USDC-as-gas account abstraction, and CCTP v2 for cross-chain USDC bridging (13 domains, Fast Transfer ~30s). USYC (Hashnote, US T-bill backed) is Circle's first native yield-bearing asset on Arc.

Circle, "Building the open agentic economy" (12 Aug 2026)
Agentic payments on Arc

Circle's post names x402 and MPP (Machine Payments Protocol) as the "value-transfer protocol" layer of the open agentic economy, with settlement in stablecoins, principally USDC, and says Arc "will carry them from day one" alongside the identity and reputation registries covered below. We do not run on Arc or settle anything ourselves; the nodes below are offline verifiers that check the shape of an x402/MPP flow against its own wire format, not a live payment.

  • art-26 Decodes and lints x402 PAYMENT-REQUIRED / PAYMENT-SIGNATURE / PAYMENT-RESPONSE headers and simulates the 402 flow.
  • art-393 Lints a header set against the x402 Protocol Version 2 wire format and flags deprecated v1 headers.
  • art-394 Validates a deferred-scheme x402 handshake, including RFC 9421 HTTP message-signature shape.
  • art-03 Models rail selection and finality across x402, card, ACH, and SWIFT for the same transaction.
  • x402-spend-evidence Three-step chain (art-590 → art-591 → art-592) that recomputes the EIP-712 digest, signer recovery, and domain/nonce window behind an x402/EIP-3009 authorization; an evidence pack, not a settlement proof.
  • art-594 Verifies a Tempo MPP cumulative session voucher offline (ecrecover, no RPC), independent of any Arc-specific deployment.
  • art-36 Parses an MPP session, checks spend cap and terms, and maps the HTTP-402 flow onto an AP2 Intent → Cart → Payment mandate chain.

Circle's post draws a line between payment volume and payment finality: "onchain settlement proves that a transaction occurred and can contribute useful evidence, but payment volume alone does not prove quality and can be manipulated." art-492, the settlement finality classifier, is the node that makes that distinction concrete: it sorts a settlement into one of three ordered finality tiers rather than treating any onchain reference as proof of completion. See the Agentic Commerce chain for how Paymaster gas abstraction and CPN settlement compose for autonomous Arc agent payments.

ERC-8004 · Identity, Reputation, Validation
Agent identity and reputation on Arc

ERC-8004 defines three registries: Identity (agentId + agentURI), Reputation, and Validation. Circle's post states these "have live implementations on public chains, and Arc will carry them from day one." None of our nodes read any of these registries onchain; each checks caller-supplied data against the registry's own schema or against an independent attestation scheme.

  • art-604 Checks a caller-supplied claimed ERC-8004 registry entry (Identity, Reputation, or Validation) against a caller-supplied on-chain read of that entry, field by field, with no hardcoded per-registry-type layout so it does not go stale as the registries evolve. Ships a ZK compute proof; see "Verifiable compute" below.
  • art-278 Aggregates a set of OCG execution receipts into a deterministic, provable reputation score. It does not read or write the ERC-8004 Reputation registry; it is a complementary, receipt-based reputation signal an agent can present alongside one.
  • art-04 Checks a KYA-OS (DIF Trusted AI Agents WG) delegated-authority credential chain: scope limits, validity windows, revocation. It does not read or write the ERC-8004 Identity registry; it is a separate, off-chain identity-attestation scheme an agent can present alongside an agentId.

Circle, "Building the open agentic economy"
Verifiable compute

Circle's post names "verifiable compute, including trusted execution environments," as one input to agent validation. We ship the first half and not the second: 97% of our live deterministic nodes (605 of 619, re-derived from chaingraph.json on every build) carry a real risc0 groth16-bn254 zero-knowledge proof that the published output came from the published kernel, independently replayable offline by anyone. We do not run or attest to any trusted execution environment; TEE-based attestation is outside our scope.

Regulatory Framework
Regulatory Citations

All Arc tools cite primary-source regulatory material. No fabricated figures. All numerical estimates (CPN fee, Arc gas price, StableFX spread) are clearly labeled as estimates and user-adjustable.

GENIUS §4
Payment Stablecoin Act (S.394, 119th Congress, signed 18 Jul 2025). Requires 1:1 eligible-asset backing: demand deposits, T-bills <93d, overnight repo on T-bills, Fed reserves. §4(a)(11) prohibits PPSIs from paying yield to holders.
MiCA Art. 54
EU Markets in Crypto-Assets Regulation Art. 54: reserve asset requirements for EU Electronic Money Token (EMT) issuers. Minimum liquid reserve; asset segregation; custody rules.
PFMI P12
CPSS-IOSCO Principles for Financial Market Infrastructures, Principle 12: Exchange-of-value settlement systems. Atomicity: final settlement of both legs simultaneously, or neither. Arc StableFX satisfies P12 for FX settlement.
BIS FX Code P35
BIS FX Global Code Principle 35: Market participants should seek to reduce settlement risk, preferring netting, PvP, and CLS-equivalent settlement where available. Arc StableFX provides PvP alternative for non-CLS pairs.
BIS Herstatt
Allsopp, Bhalla, Hackworth & Jeffery (1996): Quantifying principal risk in FX settlement. Herstatt exposure = notional × (exposure hours / 24). Used in ART-44 Herstatt credit-cost proxy calculation.
ERC-4337
Account Abstraction standard. Allows smart contract wallets as first-class users; Paymaster can sponsor or accept ERC-20 tokens (USDC on Arc) for gas. Circle Paymaster live on Arc testnet Oct 2025.
CCTP v2
Circle Cross-Chain Transfer Protocol v2. 13 domains as of Oct 2025. Fast Transfer: ~30s via LP-backed instant minting. Hooks: arbitrary execution on destination post-mint. CCTP v1 manual relay phase-out: 31 Jul 2026.
OpenChainGraph v0.3.1 · What These Tools Produce
Verifiable Execution Artifacts

Every Arc tool produces an OpenChainGraph §4 artifact: a JSON document anchored by a WebCrypto SHA-256 execution_hash over the sorted-key canonical preimage of policy_parameters + output_payload. The hash is independently verifiable by any tool that re-runs the same inputs.

  • chaingraph_version 0.3.1 · compatible with all OCG v0.3.x consumers
  • execution_hash WebCrypto SHA-256 · RFC 8785 / JCS canonical preimage · independently verifiable
  • chain block parent_hashes, parent_tool_ids, chain_depth · full DAG traceability
  • semantic_profile ISO 20022 aligned: pacs.008 (CPN/Paymaster), fxtr.008 (StableFX), acmt.023 (xReserve), pacs.009 (CCTP)
  • compliance_flags Machine-readable compliance verdict: ARC_FIT_DIAGNOSTIC_COMPLETE, CCTP_V2_VALIDATED, etc.
  • AP2 export All tools export JSON artifact + Markdown memo for direct LLM/agent consumption
  • zero PII All computations are fully client-side; no data transmitted. Verified by audit_signature in each artifact.
