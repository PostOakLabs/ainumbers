UCP Capability Negotiation

Paste a Universal Commerce Protocol business profile and a platform profile. This node computes the capability set the two parties can agree on: capabilities named by both sides at their highest mutually supported dated version, with each extension's requires bounds applied and extensions whose parents did not survive pruned away. Profile-shape findings (canonical keys[] placement, namespace authority binding, dev.ucp.* release pinning, version format) are reported alongside the verdict. Runs entirely in your browser; nothing is transmitted.

🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
Input · two UCP profiles
Paste both profiles and press Negotiate capabilities.
How it decides

Protocol phase: each side offers its ucp.version plus any older releases it maps in supported_versions; the highest mutually offered dated release is selected. Capability phase: a capability survives when both profiles carry usable entries for its name and share at least one dated version; the highest shared version is selected. Extensions (extends) survive when at least one declared parent survives; pruning repeats until stable. requires bounds on the selected protocol version and on named capabilities are verified after versions are fixed (inclusive bounds; entries declare them). Entities whose schema URL fails the namespace authority binding (reversed https host must equal the name or be a label-aligned prefix) and dev.ucp.* entries whose version differs from the profile's ucp.version are treated as not present. An empty final set is a definite outcome: the parties cannot transact under the advertised capability sets. This node is verify-only: it never fetches profiles or schemas.

Input contract

policy_parameters is an object with two required members, business_profile and platform_profile, each a UCP profile object: a required ucp member carrying ucp.version (dated release, YYYY-MM-DD), ucp.services and ucp.payment_handlers (objects, may be empty), an optional ucp.capabilities map of name to entry arrays (version required; optional schema, extends, requires), and an optional ucp.supported_versions map of older dated releases. The output payload carries verdict (AGREED, NO_COMMON_CAPABILITY, or INDETERMINATE), protocol_version, primary_reason, agreed_capabilities, dropped (with a reason per dropped name), findings, and issues (populated, with INPUT_REFUSED raised, when a profile does not meet the contract above).
