IDV/KYC Verification-Failure Incident Composer

Composes a structured verification-failure/fraud-attempt incident record from an IDV/KYC session for fraud teams, regulators, and insurers: a cross-link to the session's hash-chained receipt (ART-359), an honest failure classification (type + AR4SI severity tier), session evidence digests (OTel spans / in-toto links), remediation status, and an optional cross-link to an escalation record or a signed failure receipt. A missing session-receipt link degrades the record's claim strength rather than being silently accepted, and a malformed cross-link hash is flagged, not hidden.

IDV/KYCEvidence FormatCross-Link AwareZero PII
🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
Scope
This is an evidence FORMAT for a verification-failure incident the caller declares from an IDV/KYC session: never a fraud-detection system, never a determination of fault, never a regulatory or insurance adjudication. Fraud teams, regulators, and insurers consume this record; we do not adjudicate. Every output carries record_note restating that fence.
Session-receipt cross-link, not lookup
session_receipt references the ART-359 build_idv_session_receipt artifact's receipt_hash. This kernel checks the hash SHAPE deterministically; it does not fetch or cryptographically verify the referenced receipt. A missing or malformed link degrades record_claim_strength.
Severity class
Only affirming, warning, or contraindicated (the §22.9 AR4SI trustworthiness-vector tiers, reused from the ART-379 incident vocabulary) are ever written to the artifact. Any other declared value is coerced to warning and flagged.
