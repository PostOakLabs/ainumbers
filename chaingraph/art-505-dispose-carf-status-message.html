CARF Status Message Disposition

Takes the status message you already hold after a submission and turns it into a dispositioned break list: each returned file-level and record-level error tied to the record and the field that caused it, and each disposition countable only when a named person signed it. A disposition signed in an earlier cycle is carried forward against the same break, so the answer to why an error is still there survives from one reporting cycle to the next. Emits a hash-anchored OpenChainGraph v0.4 artifact. Consumes the output of ART-504.

OECD CARF Status Message XML Schema DAC8 Consumes ART-504 classification
🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
⚠ The return path is not assumed. The OECD Crypto-Asset Reporting Framework Status Message XML Schema, whose user guide was published on 2 June 2025, is an instrument for one competent authority to report file-level and record-level errors back to another. The OECD states it may also be used for domestic reporting of CARF information, to the extent permitted under the domestic law of the relevant jurisdiction. That is a permission, not a guarantee, and it is not the same standing arrangement as the notifications the FATCA pair consumes. So this tool asks you to declare that your jurisdiction returns a status message to you and to name the channel. Until you do, it returns a stated verdict and produces no break list rather than pretending a file came back.
⚠ Not a schema validator competing on coverage. Free CARF and CRS XML validators already exist and they validate and stop. This starts where they stop, after the authority has already answered. Error codes arrive as data and the schema version is a policy input you pin, never hardcoded here. This tool does not fetch, submit or transmit anything, it makes no claim that any output is submittable, and it is not legal or tax advice.
