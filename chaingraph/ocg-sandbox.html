Why tool_id and mandate_type aren't hashed

Only policy_parameters and output_payload enter the preimage. Metadata like tool_id and chain describe the artifact but don't affect the decision's mathematical content — hashing them would make the hash change when you rename a tool without changing any computed values. The hash is a fingerprint of the decision, not the packaging.

How OCG builds its preimage — why it's not just hash(inputs)

A naive implementation might just hash the raw JSON string. OCG specifies a 4-step canonical construction so that the hash is identical regardless of which JSON library, programming language, or runtime produced the artifact:

  1. Select only decision content: extract policy_parameters and output_payload into a new object — nothing else enters the hash
  2. Sort all keys recursively: traverse the object tree and sort every key at every level alphabetically — this removes ambiguity from JSON libraries that don't guarantee key order
  3. Stringify without whitespace: call JSON.stringify(sorted, null) — compact, no newlines, no trailing spaces — then encode to UTF-8 bytes
  4. SHA-256 via WebCrypto: call crypto.subtle.digest("SHA-256", bytes) — the browser's built-in implementation, no library dependency — and hex-encode the 32-byte result with the prefix sha256:
