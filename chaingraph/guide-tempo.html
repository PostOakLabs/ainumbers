Background
What is Tempo?

Tempo is a payments-first layer-1 blockchain designed to make programmable money work for real-world financial institutions. Mainnet launched March 18, 2026, backed by Stripe and Paradigm. The network is built around four core primitives: TIP-20 (the token standard), TIP-403 (the policy layer), MPP (the machine payment protocol), and Zones (private permissioned parallel chains launched June 2026).

TIP-20 defines the Tempo token standard: 32-byte memo fields for payment metadata, immutable currency code (USD), supply caps, and RBAC-controlled mint/burn/freeze authority. TIP-403 adds token-level whitelist, blacklist, and freeze controls that propagate across zones, which is what makes compliant stablecoin issuance and on-chain AML enforcement possible. MPP (Machine Payment Protocol) is the OAuth-for-money layer: AI agents use HTTP 402 + MPP session tokens to pay for services, live since March 2026. Zones (June 2026) are private permissioned parallel chains where operators see all transactions, users see only their own, and outsiders see only ZK validity proofs. That combination supports payroll, treasury, and institutional settlement without giving up AML surveillance.

Compliance context
Regulatory anchors

Tempo stablecoin issuers, VASPs, and operators face a dual-regime compliance landscape. The workflows above stick to the regulatory sources cited below and do not go beyond them.

US · Federal GENIUS Act (enacted): §4(a)(11) yield prohibition; 1:1 reserve requirement; monthly attestation; PPSI status determination. GENIUS PPSI AML Rule: Fed. Reg. 2026-06963 (NPRM April 2026); BSA obligations for payment stablecoin issuers. OFAC: SDN list screening for TIP-20 transfers.
EU MiCA: EU Reg. 2023/1114; e-money token (EMT) obligations include reserve requirements (Art. 36), white paper (Art. 17–19), and the supervisory regime under Title III.
FATF Travel Rule: originator/beneficiary information required for virtual asset transfers ≥$3,000. Both sending and receiving VASP obligations apply.
Standards ISO 20022: pacs.008 crosswalk (ART-40) mapping the 32-byte Tempo memo to remittance_information and sender/receiver to debtor/creditor. TIP-20 / TIP-403: Tempo token and policy specs. AP2 v0.2: Intent→Cart→Payment mandate structure. MPP: Machine Payment Protocol (github.com/tempoxyz/mpp-specs). W3C PROF: dct:conformsTo profile URIs for OpenChainGraph node classification.

How verification works on this page

Every tool on this page emits an OpenChainGraph artifact with the following properties, consistent across ART-34 through ART-41 and CRY-01.

  • chaingraph_version All nodes emit chaingraph_version: "0.4.0" in their §4 artifact payload, so consuming systems can verify schema compatibility before ingesting the artifact.
  • ISO 20022 profile Nodes are classified under two ISO 20022 semantic profiles: pacs.008-subset for payment and settlement nodes (ART-35, ART-38, ART-40) or party-identification for configuration and scoring nodes (ART-34, ART-36, ART-37, ART-39, ART-41). Profile assignment is declared in the §4 artifact metadata.
  • dct:conformsTo URIs Each §4 artifact carries a dct:conformsTo URI per W3C PROF, enabling linked-data consumers to validate artifact content against the declared OpenChainGraph profile without reading the full artifact body.
  • did:key identity The MPP Agent Mandate workflow uses did:key agent identity for the executing agent's DID and the delegation chain from human principal to sub-agent. The did:key is embedded in the ART-36 session mandate and carried through ART-04's KYA attestation.
  • execution_hash All promoted nodes emit a §4 execution_hash that covers node inputs, processing parameters, and outputs. Bilateral verification: either party in a bilateral workflow can re-run verify_execution_hash against the hash to confirm the node was run as claimed, without sharing internal policy or configuration.
