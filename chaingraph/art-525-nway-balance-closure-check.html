N-Way Balance Closure Check

Three or more internal systems state the same measure at the same moment. Each pair of them differs by some amount, and the third difference is fully determined by the other two – so a screen showing three pairwise tables enforces nothing, and leaves the arithmetic to whoever is reading it. This node runs that arithmetic: it evaluates the closure identity (A − B) + (B − C) = (A − C) against a tolerance you declare, for every triple, and names the pair that carries the break.

BCBS 239 Principle 2 fn.16 BCBS 239 §36(d) Closure Identity Enforced Internal Hops – Evidence Only
🔒 All computation runs locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
What every system below is stating. One measure, one as-of moment.
BCBS 239 §36(d) reconciles to a designated authoritative source, never consumer to consumer. Name it, and it must appear in the systems list.
Declared, never defaulted. Leave it empty and the node reports that it did not run, rather than treating every rounding difference as a break.
Three or more entries of {"system_id","balance_minor","as_of"}. Balances are integer minor units, so the arithmetic here is exact.
If your firm already reconciles hop by hop, declare each hop's own result as {"from_system_id","to_system_id","difference_minor"}. The node then checks that those independently produced hops close against each other, and that each agrees with the declared balances. This is the mode with teeth.
