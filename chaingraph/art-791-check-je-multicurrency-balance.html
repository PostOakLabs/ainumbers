Multicurrency JE Balance Check

How a journal-entry batch is tested for balance on a basis the caller declares , every currency on its own, or one declared functional currency , entirely in integer minor units, with a tolerance that is declared, never inferred, and a named refusal for every malformed input. Every number on this page is hand-computed and comes from the node's golden fixtures.

1
Step 1

The caller declares the basis for every run

The same entry can balance on one basis and fail on another, so the node refuses to guess. The balance_basis must be per_currency or functional, and an undeclared basis stops the run with BASIS_NOT_DECLARED.

A currency-conversion entry (dollars out, euros in) never sums to zero in either currency on its own, so a per-currency rule would flag every legitimate FX entry as broken. ERP and IFRS practice records foreign-currency items in the functional currency at a rate. That is why the basis is the caller's decision: the node's golden fixtures carry this exact pair , identical amounts, only the declared basis differing , one verdict imbalanced, the other balanced. The functional basis requires functional_currency (a USD, an EUR, whatever the ledger declares); omitting it is also BASIS_NOT_DECLARED.

Step 2

The integer rule for amounts

Every amount is a signed JSON integer in minor units , cents for USD at exponent 2, nothing for JPY at exponent 0, milli-units for KWD at exponent 3, all with debit positive. One sign convention, never two.

No float ever touches an amount path: the node checks the safe-integer bound explicitly and refuses amounts beyond it rather than truncating them. The golden fixtures include the boundary value accepted and the value one past the bound refused at the compute level; the browser/worker transport refuses it one step earlier, at I-JSON canonicalisation, which the fixture notes state. Currency exponents are declared by the caller and only membership is checked. The node cites ISO 4217 minor units as published by SIX, the maintenance agency, as the source to consult, but it performs no run-time fetch and does not claim the declared exponents are authoritative.

3
Step 3

Declared tolerances are echoed back in the output

Default is exact zero. A caller may declare an integer tolerance per currency, and the node echoes the tolerance it actually used next to every verdict so the output never depends on an unspoken allowance.

This is deliberately the opposite of the inferred-tolerance pattern some text-ledger tools use: integer minor units make the tolerance a plain declared number, so nothing is inferred from formatting or precision. A negative tolerance is refused outright (NEGATIVE_TOLERANCE) before any entry is evaluated. A zero-amount line never blocks an entry; it carries a ZERO_AMOUNT_LINE warning, and an entry whose lines are all zero balances at exactly zero with the warnings attached.

4
Step 4

Every malformed input lands a named refusal

Nothing is silently dropped or coerced. Each refusal is a named code, reachable by a documented input, and each one has a golden fixture proving it fires.

The cap is a named constant (500 entries) and the run refuses above it rather than processing an unbounded batch. Batch-level problems (an undeclared basis, a negative tolerance, a cap breach) stop the whole run with execution_state: did_not_run and a reason; entry-level problems refuse just that entry and the others still get verdicts, so one malformed row cannot erase the evidence for the clean ones.

5
Step 5

What this node does not claim

A balanced entry is not a correct entry. The node reports arithmetic and says so everywhere it speaks.

Sibling relationship, stated plainly: art-653 is the plain-text, single-currency, two-decimal journal-entry verifier (a parser with a Merkle evidence envelope). This node is the structured, multi-currency, declared-basis check. It shares no code with art-653 and does not extend or alter it , a sealed kernel stays sealed.

Who asks at this stepno agent yet
Any reader asks: does balanced mean booked right? No. It means the arithmetic closes on the basis the caller declared, and the residuals say by how much anything does not.
