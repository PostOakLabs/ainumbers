Agent Session Receipt Chain

Collapse an entire agent session into one tamper-evident audit object. Collect the §4 artifacts produced across a session, aggregate their execution_hash leaves into a single SHA-256 Merkle-root session receipt, then generate a regulator-framed prompt over that receipt. The session receipt is motivated by EU AI Act Article 12 record-keeping (logging obligations for high-risk AI systems) and DORA operational-resilience evidence requirements. This is a links-only narrative orchestration — there is no in-frame composer — and the terminal node emits a unified ChainGraph §4 artifact.

This chain does not begin at a single tool. Its input is the set of N ChainGraph §4 artifacts an agent produced over a session — from any suite tools it touched (mandate validations, conformance receipts, attestations, simulations, and so on). Each artifact carries an execution_hash; those hashes are the leaves of the Merkle tree built in the next node. Run whatever tools the session requires first, export each §4 artifact, and gather them.

Aggregate the Execution Receipts CRY-05
Agent-Action Audit-Trail Aggregator · aggregate_execution_receipts · cryptographic_mandate · depth:1
▼
Aggregate the N ordered session artifacts into one tamper-evident session receipt. CRY-05 builds a SHA-256 Merkle tree over the ordered leaf execution_hash values (duplicate-last on odd counts), emits the Merkle root, a per-leaf inclusion proof (sibling path), and an ordered chain-depth map (tool_id → chain_depth). It sets session_receipt_root at the top level and inside output_payload per ChainGraph Standard v0.1. This single audit object is what an EU AI Act Article 12 record-keeping log or a DORA resilience-evidence package references.
chain_depth: 1 parent_hashes: [leaf hashes] mandate_type: cryptographic_mandate Client-Side · Zero PII
Handoff → PTG-01
Export CRY-05's §4 session receipt. Its execution_hash (and session_receipt_root) becomes PTG-01's parent_hashes entry — PTG-01 consumes the whole receipt JSON as its artifact_json input.

Generate the Regulator-Framed Prompt PTG-01 · TERMINAL
AP2 Prompt Template Generator · compose_ap2_prompt · prompt_template · chain_depth:2
▼
Transform the CRY-05 session receipt into a structured, regulator-framed prompt for an external LLM — a regulatory-submission, risk-memo, or board-memo framing that encodes the relevant citations and audience conventions. No inference is performed here; PTG-01 is pure template composition that returns the prompt text and a Claude.ai deep link. It turns the cryptographic session receipt into a narrative an auditor or regulator can act on.

Terminal Node Emits One Unified §4 Artifact
This chain is links-only — there is no in-frame composer. Collect the session's §4 artifacts, run CRY-05 to fold their execution_hash leaves into one SHA-256 Merkle-root session receipt, then run PTG-01 over that receipt. The terminal node, PTG-01, emits a single ChainGraph §4 artifact whose parent_hashes reference the session receipt — closing the loop from raw session activity to a tamper-evident audit object (EU AI Act Art.12 / DORA) to a regulator-ready prompt.
