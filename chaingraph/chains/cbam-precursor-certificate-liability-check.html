CBAM Precursor Certificate Liability Check

Note (dated 2026-08-04): a chain composes independent computations performed in an analytical order. No step's output is carried into the next step by the execution model; each step computes from its own declared inputs. This is true of every chain on this site, including chains whose per-step copy below reads as a data handoff.

Four-stage check for a complex good: roll up precursor emissions, calculate consignment embedded emissions, model the certificate liability with a holding schedule and surrender deadline, and close with a session receipt over the run execution hashes. Each stage is an independent run from its own declared inputs.

CBAM Precursors · Embedded Emissions · Certificates Reg. (EU) 2023/956 3 compute steps + receipt
Chain summary
A complex-goods producer needs actual precursor data before an importer can price a consignment, and an importer needs an embedded total before a certificate liability can be modelled. This chain runs those three questions in order, as independent runs: a precursor roll-up over declared precursors, an embedded-emissions calculation over declared direct data and a declared precursor total, and a certificate cost model over a declared embedded total. Nodes: ART-72 → ART-69 → ART-71 → CRY-05.
gold border = terminal receipt stage
Stage 1: Precursor Emissions Roll-Up
1
aggregate_cbam_precursor_emissions · ART-72
Roll up embedded emissions across declared precursors for a declared final good and quantity. Each precursor carries a CN code, a mass fraction, a specific embedded emissions value in tCO2e per tonne, and a source. Mass fractions must sum to about 1.0 for reliable results. The run reports a per-precursor breakdown, a cumulative value per tonne, a cumulative total, and a data quality grade of ACTUAL_DATA, MIXED_DEFAULT_ACTUAL, FRACTION_ERROR or INCOMPLETE. The 2028 pre-consumer-scrap rule is applied only when a scrap input share is declared, and its credit modelling is a preliminary approximation to verify against final text.

Stage 2: Embedded Emissions Calculation
2
calculate_cbam_embedded_emissions · ART-69
Calculate consignment embedded emissions from declared direct and indirect data, a declared good category, country of origin and quantity, plus a declared precursor total cited from the step 1 run. The run states its emissions basis as actual or default in its own record. In the worked example the direct value is declared actual data and the indirect component uses the kernel built-in proxy factor described in the re-pin section below, so the worked example is labelled a proxy run. Filing use requires the origin-specific factor described in the re-pin section below.

Stage 3: Certificate Cost and Schedule
3
model_cbam_certificate_cost · ART-71
Model certificate liability from a declared embedded total, a declared factor year, declared EUA prices and a declared origin carbon price. The run screens the 50 tonne mass-based de minimis exemption, applies the CBAM factor for the declared year, deducts a verified origin carbon price credit where one is declared, and reports a quarterly holding schedule, a purchase window and a surrender deadline. The 2026 vintage uses quarterly-average-of-quarter-of-importation pricing. Weekly closing-average pricing applies from 2027 onward. Repurchase and cancellation are not modelled by this step.

Full Chain MCP Sequence

Run the four tools in order. Each run uses its own declared inputs. The step 2 run cites the step 1 run cumulative total as its precursor total. The step 3 run cites the step 2 run embedded total as its embedded total. No run reads another run output directly; the user supplies the cited values again as declared inputs.

Full chain: 4 MCP calls
// Step 1: roll up precursor emissions for a declared final good and quantity
const step1 = await mcp.call("aggregate_cbam_precursor_emissions", {
  final_good: { cn_code: "7308", quantity_tonnes: 100 },
  precursors: [
    { cn_code: "7201", mass_fraction: 0.6, see_tco2e_per_t: 1.8, source: "actual" },
    { cn_code: "7207", mass_fraction: 0.4, see_tco2e_per_t: 1.5, source: "actual" }
  ],
  scrap_input_share: 0
});

// Step 2: calculate consignment embedded emissions, citing the step 1 total
const step2 = await mcp.call("calculate_cbam_embedded_emissions", {
  cn_code: "7308",
  good_category: "iron_steel",
  country_of_origin: "IN",
  quantity_tonnes: 100,
  emissions_basis: "actual",
  direct_emissions_factor: 1.7,
  indirect_emissions_factor: 0.5,
  electricity_source: "grid",
  precursor_emissions: { cumulative_see_tco2e: step1.cumulative_see_tco2e },
  monitoring_method: "calculation-based"
});

// Step 3: model certificate liability, citing the step 2 total
const step3 = await mcp.call("model_cbam_certificate_cost", {
  embedded_emissions_tco2e: step2.total_embedded_emissions_tco2e,
  cbam_factor_year: 2026,
  origin_carbon_price_eur_per_t: 0,
  eua_reference_price: 80,
  eua_quarter_avg_prices: { Q1: 80 },
  import_schedule: [ { quarter: "Q1", emissions: step2.total_embedded_emissions_tco2e } ],
  annual_imported_net_mass_t: 100,
  cbam_sector: "iron_steel"
});

// Step 4: aggregate the three execution hashes into a session receipt
const step4 = await mcp.call("aggregate_execution_receipts", {
  execution_hashes: [step1.execution_hash, step2.execution_hash, step3.execution_hash]

Worked example (synthetic inputs, computed with the repo kernels)

Step 1 on 100 tonnes of CN 7308 with two actual precursors (0.6 at 1.8 tCO2e per tonne and 0.4 at 1.5 tCO2e per tonne): cumulative 1.68 tCO2e per tonne, cumulative total 168 tCO2e, data quality grade ACTUAL_DATA, scrap adjustment 0. Step 2 on the same 100 tonnes, iron and steel, origin IN, actual basis, direct factor 1.7, indirect electricity use 0.5 MWh per tonne, precursor total cited as 168: see_direct 1.7, see_indirect 0.188, see_total 1.888, total from see 188.8 tCO2e, total embedded emissions 356.8 tCO2e, data quality flag HIGH. Step 3 on 356.8 tCO2e for vintage 2026 at EUA reference price 80 EUR per tonne, origin carbon price 0, annual net mass 100 tonnes, single Q1 import of 356.8 tCO2e: CBAM factor 0.025, gross liability 8.92 tCO2e, origin price credit 0, net liability 713.60 EUR, certificates required 9, quarterly schedule Q1 at price 80 with Q1 liability 713.60 EUR and cumulative certificates 9, holding required null because the minimum holding obligation does not bind the 2026 vintage, surrender deadline 30 Sep 2027, purchase window from 2027-02-01. Step 4 aggregates the three stage hashes listed above into the session receipt root. Execution hashes, recomputed locally from the repo kernels: step 1 18290c715d5c9817eeff48d29c03c470a85add605a347373cbcc8566ae5af92a, step 2 0432b6f66cdbf2ba4981e5d2e86446b55db20ed11e61ed1455256730287eee1e, step 3 353d1d7ecdf5e4039cd301dff44613419c79318a80cae2a6d42782e1e733b00d.

Scope

Scope: decision support for pricing a CBAM certificate liability on declared inputs, under Regulation (EU) 2023/956 as amended by Regulation (EU) 2025/2083. The definitive regime runs from 1 January 2026. The CBAM factor schedule in the step 3 run is 2026: 0.025, 2027: 0.050, 2028: 0.100, 2029: 0.225, 2030: 0.485, 2031: 0.610, 2032: 0.735, 2033: 0.860, 2034: 1.000. The mass-based de minimis threshold in the step 3 run is 50 tonnes. The quarterly minimum holding share is 50 percent, applying from 1 January 2027. Certificate sales start 1 February 2027.

Out of scope

Out of scope: a filed CBAM declaration; emissions verification; surrender of certificates; a live EUA price; an origin carbon price verification; the 2028 pre-consumer-scrap rule as final law, since it is a Council position of 12 June 2026 with application from 1 January 2028 to verify against final text; any default value path through art-70, whose shipped Annex I values are illustrative placeholders and are deliberately excluded from this chain. The worked example uses synthetic inputs only. Use synthetic or anonymised inputs only for every run.

2027 surrender calendar (framing only)

The dates in this section are calendar framing around the step 3 run quarterly_holding_schedule and surrender_deadline. They are not computed outputs of any step. Appoint a verifier by Q1 2027. Obtain the verification report by 30 June 2027. Reconcile verified embedded emissions against quarterly certificate purchases. Buy any top-up certificates. Submit the annual declaration and surrender by 30 September 2027. Penalty for uncovered tonnes is 100 euros per tonne. Verification itself is external: no AINumbers kernel verifies emissions. The step 3 run does not model the repurchase window to 31 October 2027 (50 percent of prior-year purchases at original price) or the cancellation of unrepurchased certificates on 1 November 2027. Both are listed as out of scope in the step 3 kernel.

Indirect factor re-pin: 0.376 is a kernel proxy only

The step 2 kernel line is: const DEFAULT_INDIRECT_EF = 0.376, commented "tCO2e/MWh (EU-28 grid proxy - verify current edition)" and "verify against Implementing Reg." Re-pinned against its 2026 primary source, that value is NOT an adopted 2026 default value. Definitive CBAM runs from 1 January 2026 under Regulation (EU) 2023/956. Default values are under Commission Implementing Regulation (EU) 2025/2621, applying 1 January 2026 and reviewed by December 2027. For indirect emissions the definitive method uses a five-year average of the country-of-origin electricity grid emission factor. It does not use a single EU average. In the definitive period, iron and steel and aluminium take only direct emissions into account, while cement and fertilisers take both direct and indirect emissions into account. Current EU grid intensity is about 0.212 tCO2e/MWh in 2024 (Ember), so 0.376 is materially above the current EU average. The worked example on this page is therefore labelled a proxy run: its indirect component (0.5 MWh per tonne times 0.376 equals 0.188 tCO2e per tonne) uses the kernel built-in EU-28 proxy only. A 2026 filing must supply the origin-specific five-year-average factor under Implementing Regulation (EU) 2025/2621. The kernel was not changed by this package; only this page and the package body label the value correctly.

Why actual precursor data, and what every price input is

Where actual installation-level emissions cannot be evidenced, default values apply and are deliberately set high, so an efficient producer pays for someone else's inefficiency without data. The step 1 precursor_breakdown is the evidence that actual data was supplied. The step 2 run must state its emissions basis as actual or default in its own record, and a run built on defaults must be labelled as a default run. Presenting it as actual-data evidence would misstate its basis. Every price input in the step 3 run is caller-declared: the EUA reference price, quarterly average prices, and origin carbon price. The kernel fetches no market price and verifies no origin price against any registry. The step 3 output is the liability on the declared inputs only.
