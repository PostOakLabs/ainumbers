How this chain runs. Receive execution_hashes from any prior Wave-13 chain stage (wts-cross-network-dvp H3, wts-deposit-token H3, wts-settlement-asset H3, wts-collateral-mobility H3, etc.) and pass them as the cry-04 batch. The Merkle root over the full settlement decision set forms the single audit receipt a custodian, CCP, or central-bank auditor can verify. Exportable (pdf) via export_artifact.
Stage 2 (cry-05 agent-action-audit-trail-aggregator): built for agent session receipts; reframed here as a SETTLEMENT DECISION SET receipt — one Merkle-root receipt covering the finality classification, deposit-token validation, cross-network atomicity check, and participant onboarding for a single tokenized settlement. Stage 3 (ptg-01 ap2-prompt-template-generator): built for AP2 payment-mandate prompt framing; reframed here as a WHOLESALE-SETTLEMENT AUDIT MEMO — the output is a custodian/CCP/central-bank-facing cover note referencing the Merkle root, the settlement asset finality tier, and the compliance flags from the upstream Wave-13 chains. Cash/settlement-layer reframe: PFMI-style integrity evidence for the full settlement decision set — not an agent session summary. Educational tool — not a legal or regulatory attestation.
