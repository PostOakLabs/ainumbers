Index Rebalance Evidence Publication Check

Note (dated 2026-08-04): a chain composes independent computations performed in an analytical order. No step's output is carried into the next step by the execution model; each step computes from its own declared inputs. This is true of every chain on this site, including chains whose per-step copy below reads as a data handoff.

Five-stage check of an index rebalance. Record a caller-declared constituent set as of a stated date, compute a weight per constituent under a stated methodology, compile one rebalance event into a pack that cites the first two receipts, publish the pack as one sequence-numbered head-commit event for the index stream, and close with a session receipt over the run execution hashes. Every input is caller-supplied and asserted. No input is fetched from a market data source or an index provider.

Chain summary
An index administrator needs one trail from membership to published history. Membership alone does not prove weights, weights alone do not prove what changed, and a pack alone is not a sequence-numbered publication history a reviewer can order without independently discovering each artifact. This chain records a declared constituent set, computes its weights under a stated methodology, compiles one rebalance event into a pack that cites the first two receipts, and publishes the pack as one sequence-numbered head-commit event. The pack is the BMR Article 8 record set for the rebalance: it records input data, methodology, judgement reasoning, and disregard rationale as caller-supplied fields. The head lets an oversight reviewer order those records, matching the BMR Article 5 oversight function of reviewing methodology at least annually, overseeing changes and the control framework, and assessing audits and remedial actions.

Stage 1: Record Index Constituents
1
record_index_constituents · ART-557
Record a caller-declared constituent set as of a stated date, with its own execution_hash. Every constituent row, the eligibility-criteria description, and the selection universe size are caller-supplied and asserted. This step attests that a declared set exists exactly as stated, selected under the stated criteria. It makes no claim about whether the criteria were applied correctly against market data, and it performs no market data lookup. Zero-egress fence: this chain fetches nothing from an index provider or a market data source.

Stage 2: Compute Index Weights
2
compute_index_weights · ART-645
Compute a weight per constituent under a stated methodology from caller-supplied input rows, with weight_sum_check within 1e-9 of 1.0, and its own execution_hash. The step 2 run cites the step 1 receipt by execution_hash plus tool_id as a receipt citation. It does not re-derive the step 1 constituent set, and it does not verify that its input list matches any particular constituent-set attestation. Every input row is caller-supplied and asserted.

Stage 3: Compile Rebalance Evidence Pack
3
compile_rebalance_evidence_pack · ART-646
Compile one rebalance event into a pack: current and prior constituent and weight rows, diffed into additions, removals and weight deltas, citing the step 1 and step 2 receipts by execution_hash plus tool_id. The step 1 to step 2 to step 3 links are receipt citations. The pack does not re-run or independently re-derive the cited arithmetic, and it does not verify the cited receipts against a third-party feed. A reviewer must check the cited hashes against the step 1 and step 2 receipts as a manual check. The pack proves a citation. It is not a verified arithmetic result. The current and prior rows used for the diff are caller-supplied and asserted.

Stage 4: Publish Index Head
4
publish_index_head · ART-658
Publish one sequence-numbered head-commit event for the index stream, with head_hash independently recomputed by SHA-256 and seq and prev_head_hash checked. signature_valid and chain_valid are the caller's own verification claim, asserted and digested into this receipt. This node never handles private key material and never itself runs an Ed25519 verify, and head_hash is not proof of signing. A head-file tip proves the signer's claimed stream tip at that seq. It does not detect a signer publishing conflicting levels elsewhere. Signing happens off-node, before this node is called.

Full Chain MCP Sequence

Run the five tools in order. The step 2 run cites the step 1 receipt by execution_hash plus tool_id. The step 3 run cites the step 1 and step 2 receipts the same way. The step 4 run publishes the step 3 pack by its execution_hash as the head root.

Full chain: 5 MCP calls
// Step 1: record a caller-declared constituent set
const step1 = await mcp.call("record_index_constituents", {
  index_id: "EXAMPLE-INDEX",
  as_of_date: "2026-09-30",
  constituents: [
    { security_id: "SEC-A", name: "Alpha Corp", sector: "Technology", country: "US" },
    { security_id: "SEC-B", name: "Beta Ltd", sector: "Financials", country: "GB" },
    { security_id: "SEC-C", name: "Gamma Inc", sector: "Healthcare", country: "DE" }
  ],
  eligibility_criteria_ref: "Example eligibility: top 3 by declared market cap, sector diversified, synthetic only",
  selection_universe_size: 10
});

// Step 2: compute weights under market-cap methodology, citing the step 1 receipt
const step2 = await mcp.call("compute_index_weights", {
  index_id: "EXAMPLE-INDEX",
  as_of_date: "2026-09-30",
  weighting_methodology: "market-cap",
  constituents_ref: { execution_hash: step1.execution_hash, tool_id: "art-557-record-index-constituents" },
  inputs: [
    { security_id: "SEC-A", market_cap: 500 },
    { security_id: "SEC-B", market_cap: 300 },
    { security_id: "SEC-C", market_cap: 200 }
  ]
});

// Step 3: compile the rebalance pack, citing the step 1 and step 2 receipts
const step3 = await mcp.call("compile_rebalance_evidence_pack", {
  index_id: "EXAMPLE-INDEX",
  rebalance_date: "2026-09-30",
  current: {
    constituents: step1.constituents,
    weights: step2.weights,
    constituents_ref: { execution_hash: step1.execution_hash, tool_id: "art-557-record-index-constituents" },
    weights_ref: { execution_hash: step2.execution_hash, tool_id: "art-645-compute-index-weights" }
  },
  prior: {
    constituents: [
      { security_id: "SEC-A", name: "Alpha Corp", sector: "Technology", country: "US" },
      { security_id: "SEC-B", name: "Beta Ltd", sector: "Financials", country: "GB" }
    ],
    weights: [
      { security_id: "SEC-A", weight: 0.6 },
      { security_id: "SEC-B", weight: 0.4 }
    ]
  }
});

// Step 4: publish the pack as a genesis head-commit event, with caller-claimed signature validity
const step4 = await mcp.call("publish_index_head", {
  head: {
    stream: "index-head:EXAMPLE-INDEX",
    signer: "did:key:zExampleAdministrator",
    seq: 0,
    prev_head_hash: null,
    root: "sha256:" + step3.execution_hash,
    timestamp: "2026-09-30T00:00:00Z",
    proof: { type: "DataIntegrityProof", cryptosuite: "eddsa-jcs-2022", proofPurpose: "assertionMethod", proofValue: "zExampleProofValue", verificationMethod: "did:key:zExampleAdministrator" }
  },
  signature_verification: { verified: true, verified_by: "Caller-run off-node Ed25519 verification, claimed by the caller, not run by this node" }
});

// Step 5: aggregate the four execution hashes into a session receipt
const step5 = await mcp.call("aggregate_execution_receipts", {
  execution_hashes: [step1.execution_hash, step2.execution_hash, step3.execution_hash, step4.execution_hash]
});

Worked example (synthetic inputs, computed with the repo kernels)

Step 1 records 3 constituents as of 2026-09-30 under the example eligibility description, with a selection universe size of 10. Step 2 under market-cap methodology from declared market caps 500, 300 and 200 gives weights 0.5, 0.3 and 0.2, with weight_sum_check 1. Step 3 diffs the current set against a prior set of SEC-A and SEC-B at weights 0.6 and 0.4: addition SEC-C, no removals, weight deltas SEC-A 0.6 to 0.5, SEC-B 0.4 to 0.3, SEC-C null to 0.2. The step 3 pack cites the step 1 hash 57908f6e277cc424fafd45888984b3da890df9331845b0025fcdd3ac0d30a7ff and the step 2 hash 180dc6aab72405f93ae9bb4a31682b2d00be75de9568d74c26444721848a833d. Step 4 publishes the pack as a genesis head at seq 0, with head_hash sha256:f937b71a6bc8a9398dee02208241e3b175a5d7ebfb25cb428e995dd6ed37afab and signature_valid true as a caller claim. Reviewer check for the worked example: confirm the step 3 cited hashes match the step 1 and step 2 receipts shown here, because the pack itself leaves that check to the reviewer.

Scope

Scope: the pack is the BMR Article 8 record set for one rebalance, recording input data, methodology, judgement reasoning, and disregard rationale as caller-supplied fields. The head lets an oversight reviewer order those records, matching the BMR Article 5 oversight function. BMR Regulation (EU) 2016/1011 and SEBI benchmark-administrator framework references are informative context only. This chain makes no BMR or SEBI compliance claim. The domain for this chain is Securities Compliance and Corporate Governance, because the enum carries no Benchmarks value and BMR index-administration governance is the nearest fit.

Out of scope

Out of scope: a live index feed, a benchmark-publisher scorecard, verification of eligibility criteria against market data, verification of the cited arithmetic by the pack, signature verification by the head node, equivocation detection for conflicting signer publications, a restatement record (art-647 sits outside this chain), and five years of retained market data storage. BMR Article 8 requires records kept for at least five years in a form that allows the calculation to be replicated and fully understood. These nodes attest declared inputs. They do not store five years of market data. A receipt is not a retained record. The worked example uses invented constituents. Use synthetic or anonymised inputs only for every run.
