ART-838 · OpenChainGraph · Control Frequency Sample

Control Frequency Sample

Give this node a control’s frequency, the size of the population of instances you are sampling from, and a policy table you declare. It returns the sample size from the table row for that frequency, says whether the population falls inside the range the table expects for that frequency, and derives an integer start offset from the population hash you declare, then spreads the selected indices evenly across the whole population.

compliance_control server compute values only, zero network no randomness proof deferred

Applies a table you declare. It ships no table, and is not guidance from any audit firm or standard-setter. The sample size is only as defensible as the table.

What it does

The same question comes up on every audit or control-testing cycle: how many instances of a monthly control do we test, and how about a weekly or a daily one? Sample sizes are a matter of policy, so this node does not carry them. You pass a table with one row per frequency, and the node applies the row for the frequency you name.

Output
sample_sizetaken from your table row, never computed
within_expected_rangewhether the declared population lies between the row’s min_population and max_population
start_offseta fold of population_hash, modulo population_size
selected_indicesfloor((start_offset + i × population_size) ÷ sample_size) for i from 0 to sample_size − 1, unique and in range, replayable from the same hash
frequency_rowthe table row that was used, echoed back

A population outside the expected range, such as 40 instances of a control declared monthly, is flagged POPULATION_OUTSIDE_EXPECTED_RANGE. The node still plans the sample from the declared row and never silently corrects the population or the frequency, because the mismatch is itself a finding for the reviewer.

Selection is systematic sampling over a population hash you commit to before the call, using integer arithmetic only, so every position in the population can be selected for some hash. There is no random number generator and no clock, so a verifier can replay the exact selection.

Input manifest

policy_parameters
control_frequency (required, string)a frequency id that matches one table row, for example monthly
population_size (required, integer ≥ 1)number of instances of the control in the period
population_hash (required, string)hash of the sorted population extract, declared by you
period_days (required, integer ≥ 1)length of the testing period, echoed in the output
policy_table (required, array)rows of frequency, min_population, max_population, sample_size (integers)

Refusal codes (compliance_flags ["INPUT_REFUSED"]): CONTROL_FREQUENCY_MISSING, POPULATION_SIZE_INVALID, PERIOD_DAYS_INVALID, POPULATION_HASH_MISSING, POLICY_TABLE_MISSING, POLICY_TABLE_ROW_INVALID, FREQUENCY_ROW_MISSING, FREQUENCY_ROW_DUPLICATED, SAMPLE_SIZE_EXCEEDS_POPULATION, SAMPLE_SIZE_EXCEEDS_LIMIT (above 100000). A frequency or hash that is not a string is refused with the matching MISSING code. A refusal returns no sample size and no indices.

Every table in the conformance fixtures is synthetic and illustrative, labelled as such in the fixture names. None of those values is a recommended sample size.

Provenance

Selection over a caller-declared population hash follows the same method as the attribute sampling plan node (ART-458); the code is a copy, not an import. This page and the node are CC BY 4.0.
