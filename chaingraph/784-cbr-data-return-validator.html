CBR Data Return Validator

Validates an aggregate correspondent-banking data return (a bank's or money transfer operator's periodic counts of active correspondents, terminations, corridors and volumes by key currency) against an illustrative, profile-driven template: completeness, internal consistency, key-currency and concentration checks, plus a message-quality readiness roll-up from the existing address and LEI lint summaries. Everything runs locally on aggregate values only, so an institution can check a return before submission and nothing leaves the machine.

🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
This template is illustrative. It is built from public correspondent-banking metric definitions and is not the official data collection template of the Pacific correspondent-banking project (that template is still being finalised) and not the World Bank CBR Resilience Index (its calibration is pending). Swift deferred its payments structured-address change on 27 August 2026 and undertook to give an update by December 2026 at the latest, so no hard migration date is asserted here; the readiness framing follows the FATF revised Recommendation 16 of June 2025 with its end-2030 transition.
Return input (aggregate values only)


    

  


  

    
What this node checks

    

      
RuleCheckOutcome

      
REQ-*Required fields per profile: period, institution type, pseudonymous code, at least one currency block with corridors; the pacific profile also requires USD, AUD and NZDviolation

      
COUNT-ROLLFORWARDClosing active correspondents equals opening plus opened minus terminated or restricted, per currencyviolation

      
CORRIDOR-SUM-*Corridor sums equal the stated currency totals: counts exactly, values within a stated 0.5 percent toleranceviolation

      
PERIOD-SANITYReal calendar dates, end on or after start, span at most 400 daysviolation

      
STRING_LEAF_OUTSIDE_ENUMERATIONAggregate-only contract: any string leaf outside the enumerations and the FI-NNN code pattern (a name, BIC, LEI or account identifier) is refused naming the JSON path only, never echoing the valuerefusal

      
KEY_CURRENCY_SINGLE_CORRESPONDENTExactly one active correspondent in a profile key currency: the single-point-of-failure watch itemflag

      
CONCENTRATION_*Top corridor share above 0.80, or Herfindahl-Hirschman index over corridor outbound-value shares above 0.50flag

      
readinessRoll-up of supplied message-quality summaries (structure mix, valid LEI) into percentages and a band; reports not_supplied when absentreport

    

    
The two per-message linters this node builds on are separate tools: the CBPR+ structured address linter (art-241) and the LEI payment binding linter (art-246). This node consumes only their aggregate summaries and never reimplements their rules.
