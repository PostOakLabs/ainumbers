Payment Data Migration Completeness

Verifies that historical data moved from a legacy system to a successor is complete, value-preserving, and reconcilable — the evidence a migration actually needs. You declare per-partition source and target record counts and control totals (by period, agency, or rail — whatever partition scheme fits your migration), known exclusions with reasons, declared transformation rules, and any fields you observed changed. This tool never reads your source or target dataset: it reconciles the figures you already have. It checks every partition individually as well as the aggregate, because an aggregate that nets to zero while individual partitions do not is the failure a rushed sign-off misses. Emits a hash-anchored OpenChainGraph v0.4 artifact. Region-portable: every fact below is an input you declare, never a hardcoded country, currency, agency, or rail.

🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
⚠ This tool does not read your source or target dataset — you supply counts and totals your migration tooling already produced. A clean result is not a determination that any underlying data quality control has been met; it is an arithmetic reconciliation over the figures you declare. It computes once when you press the button, stores nothing, runs on no schedule, and retains nothing.

    What this does not do
    
    
    It does not read your source or target system, extract records, or compute a migration from raw data — you run that separately and declare the counts and totals here. It is not a regime-specific migration tool: it does not validate ISO 20022 address fields, VIDA recapitulative statements, x402 protocol versions, or TLS/PKI cutover, and it does not score migration readiness maturity. A clean result is not a determination that any underlying data quality control has been met, and where a partition was verified by sampling only, this tool reports that as a residual-risk statement rather than a completeness verdict.
    
  
    

  
    
    
    Related
    
    
    Prior art it does not duplicate, all regime-specific: ART-161 (VIDA recapitulative statements), ART-393 (x402 v2 protocol), ART-86 (TLS/PKI), RCA-03 (ISO 20022 PostalAddress24 fields), and 101 (ISO 20022 migration readiness scoring across 7 maturity dimensions — a self-assessment, not a completeness verifier). This node is the generic completeness verifier none of those provide. Part of the government-payment-lifecycle chain alongside the programme's other audit-evidence nodes as they ship.
