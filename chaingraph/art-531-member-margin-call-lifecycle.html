Member Margin Call Lifecycle

Attests whether a clearing member's margin call was funded within the CCP's own published timing rule; it is not a workflow engine. You declare the call's state timestamps (issued, confirmed, funded, or disputed and escalated as a contingency path), a declared SLA window in minutes, and an evaluation point for a call that is still open. This tool checks that the declared timestamps are chronologically consistent, computes elapsed minutes against the declared SLA, and emits an informational suggested gate route. Emits a hash-anchored OpenChainGraph v0.4 artifact. Region-portable: currency and the SLA window are inputs you declare, never a hardcoded CCP or jurisdiction.

Lifecycle state tracking, issued through funded Dispute / escalation contingency path SLA attestation against a declared window
🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
⚠ This tool does not implement any margin-call workflow or escalation engine; the suggested gate route is informational only. It is not a determination that any underlying control has been met; it is a state/attestation fact over the timestamps you supply. It computes once when you press the button, stores nothing, runs on no schedule, and retains nothing. Member reference is an opaque string you supply, never a raw member identity.

    What this does not do
    
    
    It does not issue, transmit, or route a margin call to anyone, and it does not implement any escalation workflow; `suggested_gate_route` names what a §27.4 gate_policy consumer could do with this result, it does not itself act on it. It does not verify that the figures you supply are complete or accurate, and a clean attestation is not a determination that any underlying control has been met.
