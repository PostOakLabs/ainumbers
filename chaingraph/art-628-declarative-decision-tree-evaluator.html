Declarative Decision-Tree Evaluator

Evaluates a caller-supplied, hash-pinned decision tree against caller-supplied facts entirely offline, client-side. The tree is inert data: one audited interpreter walks it over a closed operator set (eq, in, lt, lte, gt, gte, between, all_of, any_of, none_of), never eval, never a function-valued criterion. Every node in the tree, internal criteria included and not leaves only, must carry a citation to a pinned clause snapshot; a tree with any uncited node is rejected by the loader. The interpreter independently recomputes the tree's own tree_digest from its bytes and refuses to evaluate on a mismatch, never trusting the declared digest as an oracle for itself. Evaluation walks an explicit stack, not recursion, and acyclicity is checked at load, before any evaluation begins.

Scope & reliance
This kernel carries no embedded classification rules of its own. The demonstrator tree below is one caller-supplied example, the Reg D Rule 501(a) entity-type accredited-investor category test, citing 17 CFR 230.501(a)(1), (2), (3), (8) and (9). It is a category test only: the natural-person prongs and the two numeric-threshold entity prongs of Rule 501(a) (net worth, income, and the $5m "investments" definition's own numeric test) are out of scope for this demonstrator and are not evaluated here. Every criterion in this tree reads a bounded enum (boolean), so it was enumerated exhaustively: 25 = 32 combinations, 0 unexplained results. This tool does not reproduce CFR text and does not assert that any entity is in fact accredited. No formal correctness proof exists for this node yet; see the proof-status note below the results.
