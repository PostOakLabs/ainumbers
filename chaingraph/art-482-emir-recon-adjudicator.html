EMIR Trade-Repository Reconciliation Adjudicator

Under EMIR Refit, the trade repository (TR) runs the inter-TR reconciliation and returns a daily ISO 20022 response naming the matched/unreconciled fields per UTI — a firm holds that response plus its own submitted state, never both counterparties' raw extracts. This tool independently reproduces the reconciliation verdict from the TR response + your submitted state, under a policy-supplied field/tolerance/suppression table, and treats disagreement with the TR's own verdict as a first-class result, never an error. Not art-156 emir-counterparty-pairing-reconciler, which compares two counterparties' extracts directly — a premise EMIR Refit's TR-mediated model replaced for the reconciliation step. Step 1 of the EMIR Inter-TR Reconciliation Cycle, where an open break set routes cycle sign-off to a §27 review_required gate with the reporting-operations owner as reviewer.

🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
⚠ The field/tolerance/suppression table is a per-cycle POLICY INPUT, not a fixed list — the ESMA EMIR Refit reconciliation-tolerances table (ESMA74-362-2683) reconciles 87 fields at go-live, with 61 more (148 total) added by Phase 2 (27 Apr 2026 EU / Sep 2026 UK). Re-derive your own field/tolerance table from the current ESMA release each cycle; this tool does not ship or assume one.
