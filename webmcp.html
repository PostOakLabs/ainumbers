WebMCP: the pages on this estate that an agent can call

This page is for practitioners who want their browser tools to be reachable by AI agents without standing up a server. On this estate, WebMCP means that a published page registers the tool it carries, an agent discovers that registration in one machine-readable file, the agent calls the tool, and the artifact that comes back verifies through a public utility. Each step below draws one link in that loop, and the directory at the end lists every WebMCP surface here with a link you can follow.

Every registration lives in a file any agent can fetch: .well-known/webmcp.json, with a signed snapshot beside it. Read it after this page and the loop below stops being a drawing.

Step 1 · The loop

The loop from registration to verified answer

A tool page publishes a registration for the kernel it carries. An agent that knows nothing about the site fetches one well-known file and finds that registration by name. The agent calls the tool with its arguments, the page runs it client-side, and the artifact that comes back carries a hash the agent can confirm with the public verify_execution_hash utility before it trusts the answer.

The registration and the discovery file are the contract; nothing about the loop depends on where the agent runs. The signed snapshot beside the discovery file lets a verifier confirm that the registrations it read today are the ones the estate published. Verification closes the loop: a tool that answers without a recomputable artifact is a claim, and this estate ships tools that ship evidence.

Step 3 · Meta budgets

How registrations stay small enough to fetch

A discovery file is only useful while it stays cheap to read, so every tool registration passes through a lint before it ships. The budget rule set bounds each tool name and description, and the check-webmcp-meta-budgets gate reports any registration that outgrows its budget. Declare the tool within budget, let the lint read it, then ship it into the discovery file.

The gate runs in report mode by default and as a down-only ratchet against a pinned baseline, so the estate can sweep old violations over time while the count never climbs back up. The budgets themselves follow a published community rule set for tool metadata, ported with attribution rather than copied bytes.
