## Severity 1 — Contract violation + your stated cleanup target: the lang toggle

**What:** The deferred multilingual toggle (`.lang-bar` UI, `setLang()`, the multi-language `L`/`TRANSLATIONS` object, `t()` accessor, `data-i18n` attributes, and `sessionStorage['ain_lang']` read/write) is still embedded in ~250+ files — **including the canonical template `tools/152-baas-provider-comparator.html`** and root pages (`index.html`, `about.html`, `contact.html`, `mcp.html`, `sitemap.html`).

**Why it's a violation, not just cleanup:**
- CONTRACT §0 (Immutable Hard Constraints) forbids **all** client storage. §1.1 explicitly states the `ain_lang` sessionStorage exemption was **removed**. Every file that still calls `sessionStorage.setItem('ain_lang', …)` / `getItem('ain_lang')` is now **out of contract**. The `sessionStorage` grep that returned 250+ files is almost entirely this — not real state persistence.
- §1.1 also records the product judgment: the toggle "was cosmetic only — it did not translate content, providing no value and a misleading UX." In practice the `L` objects **do** carry translated chrome strings (ES/FR/AR/PT/中文), so the live behavior is *partial* translation of headers/footers/labels while the analytical body stays English — arguably worse than no toggle, because it signals a capability the tool doesn't deliver.

**Cost of keeping it:** On the early tools the translation blocks are enormous — e.g. `04-fraud-score-simulator` carries ES at ~L1868 and PT at ~L2132; `06-fednow-lookup` runs translations to ~L3097. These blocks are frequently **30–50% of the file's total bytes**. Removing them materially shrinks the deploy and the AI-context footprint of every file.

**Why removal is mechanical but not a blind delete:** render code calls `t('key')` heavily (the canonical template alone has **48** `t()`/`setLang` references). Ripping out `L` entirely would break every `t()` call that has no English default in the HTML.

### Recommended removal recipe (safe, uniform, zero render-risk)

Per file:
1. **Keep** `L.en` and the `t()` accessor, but hard-pin it to English: `function t(k){ return (L.en && L.en[k]) || k; }` — drops the `sessionStorage` lookup that currently lives inside `t()`.
2. **Delete** the five non-English sub-objects (`L.es`, `L.fr`, `L.ar`, `L.pt`, `L.zh` / `中文`). This is the 80% byte win.
3. **Delete** the `.lang-bar` CSS rule and the `.lang-bar` HTML block (the EN/ES/FR/AR/PT/中文 button row).
4. **Delete** `setLang()`, the auto-apply IIFE `(function(){…sessionStorage.getItem('ain_lang')…})()`, and any `setLang(saved)` / `applyHero(saved)` calls. **This removes the §0 violation.**
5. `data-i18n` attributes can stay (harmless) or be stripped in a later cosmetic pass — the English default text already sits inside each `data-i18n` span, so the page renders in English with no JS.

A later optional pass can inline `L.en` into the markup and delete `t()` entirely. Not required for compliance.
