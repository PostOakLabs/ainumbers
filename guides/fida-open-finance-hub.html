Typical Workflow

FIDA Strategy & Compliance Journey

Follow this six-stage workflow to move from initial FIDA scope assessment through to an investment-grade open finance business case.

  1. 1

    Map FIDA data scope (banking & cross-sector)

    Use T360 and T410 together to determine which data categories across banking, investment, insurance, and pension are in scope and when Phase 1/2/3 obligations apply.

    T360 Data Scope MapperT410 Cross-Sector Mapper
  2. 2

    Check permission scheme applicability

    Run T408 to determine which data falls under the FIDA permission scheme versus existing PSD2/PSD3 consent obligations, and identify GDPR Art. 20 overlaps.

    T408 Permission Scheme Checker
  3. 3

    Assess FIP authorisation readiness

    If pursuing a Financial Information Provider licence, use T407 to gap your application against FIDA Art. 14–25 and generate a prioritised readiness action plan.

    T407 FIP Readiness Builder
  4. 4

    Model API monetisation

    Use T409 to model tiered API pricing scenarios, cost-to-serve, and break-even timelines for your open finance API product portfolio.

    T409 API Monetisation Calculator
  5. 5

    Model data product revenue

    Use T377 to model revenue scenarios for data products: enrichment APIs, analytics, and embedded finance data licensing: with sensitivity analysis.

    T377 Data Product Revenue Modeler
  6. 6

    Build the investment business case

    Feed T409/T377 outputs into T411 to build a 5-year NPV business case with payback period and sensitivity analysis ready for investment committee.

    T411 Business Case ROI Modeller

Regulatory Coverage

FIDA & Open Finance Framework Coverage

Tools in this hub are mapped to obligations under the following frameworks. Verify current applicability with qualified legal counsel: FIDA is at proposal stage and RTS are in development.

🇪🇺 EU FIDA

COM/2023/360 Financial Data Access Regulation. Data holder obligations, FIP authorisation (Art. 14–25), permission scheme, and phased data scope implementation timelines across banking, insurance, pension, and investment.

🇪🇺 PSD2 / PSD3

PSD3 (COM/2023/366) replaces PSD2. Account data access, SCA, open banking API standards, and liability regime. FIDA permission scheme overlaps and delineation from PSD3 access rights.

🇬🇧 Open Banking UK

CMA Open Banking Order. OBIE API specifications, AISP/PISP regulatory framework, and Consumer Duty obligations for open banking-derived services. Comparative baseline for FIDA scope assessment.

🇺🇸 CFPB §1033

Personal Financial Data Rights (Oct 2024). Consumer-authorised data sharing for covered data providers. Third-party access conditions, revocation rights, and developer interface standards: a global comparative baseline.

Quick Start

Get Started in 4 Steps

  1. 1

    Map your FIDA data scope

    Open T360 FIDA Data Scope Mapper to map your data categories into FIDA scope. Then run T410 Cross-Sector Scope Mapper if you hold insurance, pension, or investment data.

  2. 2

    Check permission scheme scope and FIP readiness

    Use T408 Permission Scheme Scope Checker to delineate FIDA from PSD2 obligations. If applying for a FIP licence, run T407 FIP Authorisation Readiness Builder for a gap score against Art. 14–25.

  3. 3

    Model API monetisation and data product revenue

    Run T409 API Monetisation Calculator for tiered pricing scenarios, then use T377 Data Product Revenue Modeler to model data-as-a-service, analytics, and embedded finance revenue streams.

  4. 4

    Build the 5-year business case

    Feed T409 and T377 outputs into T411 Open Finance Business Case ROI Modeller to generate a 5-year NPV model with payback period and sensitivity analysis for investment committee approval.
