4 Stages · Live Chain RBE-06 · T285 · T320 · T288 ~60 min end-to-end Client-side · Zero PII
How this workflow works: Open each tool in a new tab using the Launch button. Complete the tool and copy its key output (JSON snippet, score, or summary). Paste it into the capture field below the tool button. Mark the stage complete to advance. This page stays open throughout — it tracks your chain and assembles the final export report.

The Agentic Mandate Sandbox lets you simulate agent payment policies for tokenised A2A corridors — spend caps, MCC allowlists, velocity rules, expiry, and cross-currency handling. It generates AP2-compatible policy JSON that becomes the source of truth for the formal mandate in Stage 2. Run the sandbox, configure your policy parameters, and export the policy scaffold JSON.

Use the policy scaffold from Stage 1 as the input for the Google AP2 Checkout / Payment Mandate VDC Builder. The builder formalises the mandate as a Verifiable Digital Credential — adding identity binding, credential proofs, and schema validation against the AP2 Open or Closed Wallet spec. This is the artefact your agent runtime will present when initiating a payment. Export the full mandate VDC JSON.

Passing to Stage 3 — AP2 Policy Validator

Run the AP2 mandate JSON from Stage 2 through the AP2 MCP Policy Validator. The validator checks the payload against the Unified Build Contract v1.0 schema, auto-generates MCP tool definitions from the mandate, and simulates agent ingestion of the agent_instructions array. This confirms the mandate is correctly structured for MCP agent runtime consumption before you proceed to the deployment readiness check in Stage 4. Capture the compliance score and any gap items.
