The page-registered tool

Demo 1 records a real WebMCP session with its errors intact. This page is a technical, click-by-click procedure for checking whether a ChainGraph page has registered its deterministic compliance tool with the browser agent surface, running the human-facing calculation, and verifying deterministic results. Part A is one-time browser setup; Part B is the reproducible test procedure.

WebMCP art-129 · WebBotAuth Signature Verifier Client-Side · No Server Calls Zero PII
Part A

One-time setup, before the presentation

Three steps, needed once per computer. Allow ten minutes the first time.

  • 1

    Open the Chrome flags page

    chrome://flags/#web-mcp

    Paste the address into Chrome's address bar and press Enter. If the page reports "not found", open chrome://flags and enter WebMCP in the search box at the top.

    Expected result: a highlighted row named "WebMCP" or "Web Model Context".
  • 2

    Enable the flag, then relaunch

    On that row, change the dropdown from Default to Enabled. A Relaunch button appears at the bottom right; click it and Chrome restarts on its own.

    No WebMCP row listed? Search the flags page for Experimental Web Platform features, set that entry to Enabled, and relaunch.
  • 3

    Open the demo page and confirm the setup

    https://ainumbers.co/chaingraph/art-129-webbotauth-signature-verifier.html

    Open the page, press F12 to open DevTools, select the Console tab, and click once inside the console area.

    On a first-ever paste, Chrome blocks the console with a security warning. Type the two words allow pasting and press Enter; this is required once per machine. Then paste and run:

    typeof document.modelContext
    Expected result: 'object'. Setup is complete and does not need repeating on this computer.
    Result is 'undefined'? The flag did not take effect, usually because a background Chrome process survived the relaunch. Close Chrome fully, press Win+R, and run "C:\Program Files\Google\Chrome\Application\chrome.exe" --enable-features=WebMCP to start Chrome with the feature enabled directly. Demo 1, step 3, records this failure and its diagnosis in full.

    As a final confirmation, list the tools the page has registered:

    await (document.modelContext ?? navigator.modelContext).getTools()
    Expected result: an array of browser-registered tools. To continue with the agent test in Part B, it must contain verify_webbotauth_signature.
    The named tool is absent? WebMCP is available, but this page has not completed the separate registration step needed for browser-agent use. The human-facing verification can still run, but do not claim that an agent can invoke this page through WebMCP until the named tool appears in this list.
Part B

Reproduce the page-registered tool

Run these steps in order. They explain what the page exposes, how to exercise the human interface, and how to check the browser's agent-facing tool registry. The page and the browser must both satisfy the expected results before an agent can invoke the tool.

  • 4

    Inspect the tool definition

    On the art-129 page, press Ctrl+U to open its source in a new tab. Press Ctrl+F, search for verify_webbotauth_signature, and press Enter.

    Expected result: the tool definition names verify_webbotauth_signature and lists its input fields: covered components, signature parameters, a base64 signature, a public-key JWK, algorithm, expected tag, and timestamps.

    The definition is the contract an agent needs before making a call. It describes the required data and prevents the agent from inventing field names or guessing how a signature should be represented.

  • 5

    Load a synthetic verification request

    Close the source tab and return to the page. In the input area, select the accept sample or example. The sample fills the form with a non-production Ed25519 signature, covered components, signature parameters, a public key, and fixed timestamps.

    Expected result: every required field is populated. The sample is safe for demonstration because it contains no customer data, credentials, or live requests.
  • 6

    Run the human-facing calculation

    Click Verify or Run on the page. The browser reconstructs the RFC 9421 signature base, verifies the Ed25519 signature with the supplied public key, checks the declared algorithm and tag, and evaluates freshness from the provided timestamps.

    Expected result: the accept sample returns an ACCEPT verdict, named passing checks, compliance flags, and an execution_hash.
    REFUSE instead? Use the accept sample again and confirm that the signature, signature parameters, public-key JWK, algorithm, and timestamps were all loaded before running the tool.
  • 7

    Check determinism and a controlled failure

    Click run again without changing anything.

    Expected result: the result and execution hash are identical because the inputs and calculation have not changed.

    Next, change one character in the signature field, then run the calculation again.

    Expected result: the verdict changes to REFUSE, the cryptographic-signature check fails, and the execution hash changes because the input and output are now different.
  • 8

    Confirm browser-agent registration

    Open DevTools with F12, select Console, and paste the following check. This does not invoke the tool. It only asks the browser which tools the current page has registered for WebMCP.

    (async () => { const mc = document.modelContext ?? navigator.modelContext; if (!mc) throw new Error("WebMCP is unavailable; complete Part A and reload the page."); const tools = await mc.getTools(); const tool = tools.find(t => t.name === "verify_webbotauth_signature"); if (!tool) throw new Error("The page has not registered verify_webbotauth_signature."); console.log({ name: tool.name, description: tool.description, inputSchema: tool.inputSchema }); })();
    Expected result: the Console prints the tool name, description, and input schema. An agent can use this schema to construct an invocation using the same synthetic values loaded in step 5.
    Tool not registered? WebMCP is enabled but this page has not registered the named tool on the browser agent surface. Treat that as a failed prerequisite: reload after completing Part A, then inspect the page's registration code before attempting an agent call.

If a prerequisite fails: use Demo 1 for a complete browser-level diagnostic of WebMCP availability, registration, invocation, and receipt verification. Do not treat a missing registered tool as a successful agent integration.
