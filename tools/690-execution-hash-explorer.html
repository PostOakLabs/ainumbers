Trust Surface · Execution Hash

Verification by recomputation without a trusted signer

Every OpenChainGraph artifact carries a SHA-256 execution_hash. The hash covers exactly two members, policy_parameters and output_payload, serialized in canonical JSON form. Paste any artifact below and this page recomputes the hash the same way the worker does, then shows you the bytes: what canonicalization changed, where the preimage boundary sits, and how the artifact chains to its parents through parent_hashes.

🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.

View 1 · Raw versus canonical

What canonical JSON did to the bytes

The hash is never taken over the artifact as you pasted it. Canonicalization (RFC 8785 JCS over the I-JSON subset) sorts object member names by code unit, keeps array order, and emits minimal whitespace.     View 2 · The preimage boundary
    
Exactly which bytes are hashed

    
The execution_hash preimage is {policy_parameters, output_payload} and nothing else. Members that describe, sign, or chain the artifact sit outside the boundary: they can change without moving the hash, which is why signatures and anchors cover the hash itself rather than duplicating it.

    View 3 · The parent_hashes walk
    
      Where this artifact sits in the chain
      
    
      An artifact names its inputs by hash. Each entry in parent_hashes is the execution_hash of a parent artifact, and chain_depth counts links back to the root. Walking the chain is walking hashes all the way down, each step recomputable the same way you just saw.
      
    
      
  
      

  
      
    The boundary of this page
    
      The hash, not the signature
      
    
      This is the teaching surface for the hash alone. It recomputes and compares execution_hash values; it does not verify Ed25519 signatures, RFC 6962 Merkle inclusion, or batch receipts. Those live in the estate's receipt verifier, which recomputes this same hash on its way to signature and inclusion checks. The worker applies the identical recomputation server-side: same preimage, same canonicalizer, same answer.
