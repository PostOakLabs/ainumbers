OTel Span Receipt Verifier

Take an OTLP/JSON trace and generate one receipt per span: a canonical span digest, the parent-span's receipt digest (so the receipt chain mirrors the span tree), the pinned gen_ai attribute snapshot in force, and an eddsa-jcs-2022 signature. All span receipts roll up into a single Merkle-rooted trace receipt. Paste any trace + bundle back in to verify it – recompute every digest, walk the parent chain, rebuild the Merkle root, and see exactly which spans are attested, unattested, or tampered.

Receipt Per Span RFC 6962 Merkle Root eddsa-jcs-2022 v1.0
Scope fence – read before use A span receipt proves this exact span content, at this position in the span tree, was attested by whoever holds the signing key, at generation time. It does not prove the underlying operation was computationally correct (that is OCG §18, a separate claim), and it does not prove real-world timing accuracy – it binds to whatever startTimeUnixNano/endTimeUnixNano the trace already carries. The gen_ai attribute namespace has zero tagged upstream releases, so semconv_snapshot is this tool's own dated pin, stamped into every receipt, and expected to drift as the upstream spec moves. Signing keys here are ephemeral (or pasted by you), not anchored to any external identity registry. Zero network export: this page never opens an OTLP or network connection. Everything stays in the browser; use the download buttons to save files.
🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
