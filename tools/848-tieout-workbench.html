How the binding works, and what it says

Four checks run per span, in order: the SHA-256 of the supplied bytes equals the recorded document digest; the named locator resolves in a parse of the same bytes by the pinned RFC 4180 parser (or an RFC 6901 walk for JSON); the extracted string equals the recorded lexical byte for byte; and the canonical digest of the normalized lexical equals the canonical digest of the value at the input pointer, when that value was supplied. The state marks:

✓ verifiedthe document was in hand and all four checks passed: the value is bound to this document at this location.
◐ externalthe mapping is complete and self-consistent; the input's current value was not supplied, so the fourth check had nothing to bind against.
✗ faileda check refused; the reason code is printed and the mapping never enters the batch.
§A tick mark on this page is a tie-out aid: this does not show the document is accurate.

The extractor is pinned: , checked against the published kernel digest list vendored as-of . Records naming any other digest are refused.
