Treasury & Revenue · T626 · GloBE Information Return

GIR Data-Point Completeness Analyzer

Declare which GloBE Information Return data points your own systems can populate today, declare the facts that switch the conditional points on, and get back a per-point map of what is populated, what is partial, what is missing, and what is not applicable to you. Jurisdiction-level profit and tax data is exactly the data nobody wants to paste into a hosted service, so this page computes entirely in your browser: nothing you type is transmitted anywhere, there is no server call, and there is no storage of any kind.

⚠ This page maps a data inventory you declare against the published GIR data-point structure. The coverage figure is a count over that declared inventory and nothing more. It is not a filing conclusion, it does not check any value you hold, and it never states that a return can be submitted. Elections and characterisation judgments stay with the filer.
GloBE Information Return Gap Analysis Zero PII Client-Side
Scope & reliance: This is a readiness map over data points, not a return composer. It does not assemble a GIR, does not render GIR XML, and does not evaluate any amount. It reports which data points your declared inventory covers. Permitted vocabulary here is populated, partial, missing, conditional. Deterministic logic · no inference · zero PII · CC BY 4.0.
🔒 All inputs are processed locally in your browser. No data is transmitted. Do not enter real personal data — use synthetic or anonymised inputs only.
Inventory Source
The data-point structure below was derived from the primary OECD publication named here, at the section granularity the publication itself uses. State which structure your inventory was mapped against: this is a declared input, not a fixed constant.
Declared Facts
Tick the facts that are true of your group. These are what make a conditional data point applicable. Anything left unticked makes its dependent points not applicable, and the report names the condition in both cases.
Your Declared Data Inventory
One data-point reference per line, optionally followed by a status of populated, partial or missing. A line with no status is read as populated. Anything not listed is treated as missing. Lines that match no known reference are reported separately rather than silently dropped.
